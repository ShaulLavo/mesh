# Mesh contributor guidance

Read [CLAUDE.md](CLAUDE.md) before working here. Its working agreement, invariants,
conventions and verification requirements remain binding.

## Copy

- Say what a thing is and does. Use plain words. Avoid "rather than", "instead of"
  and emphatic negative rewrites. Plain facts such as "No sessions" are fine.
- Status and error text says what happened. When action is needed, name the next
  command or control and the machine or location where it belongs.
- Keep implementation identifiers out of default screens unless needed for an
  action. Preserve useful diagnostics in an accessible details view or logs.
- Use the ellipsis character … for unfinished work. Keep unknown, pending and
  failed states distinct, and update copy assertions with the text they check.
